## 2. 產品目標

一句話：把「這件衣服穿在我身上、站在那個場景裡適不適合」變成可立即調整的畫面。

目標使用者為 18–30 歲、會收藏網拍截圖、對購買衣服猶豫的人。核心入口與文案聚焦「買之前先試搭」。一次成功體驗是：選擇像自己的替身 → 匯入一件想買的衣服 → 調整搭配與場景 → 完成對比卡 → 儲存或分享，幫助做購買決定。

首次使用後，回訪使用者應能在約 10 秒內看見內建衣物試搭結果。這是互動目標，不是對去背、照片分析或外部服務延遲的無條件承諾。

免費核心操作、草稿、衣物與作品均在裝置端運作，不要求登入。購買連結只儲存來源，不導入結帳系統。MVP 不做尺寸合身預測、布料物理模擬、推薦演算法或保證「實際穿起來一樣」。

## 4. 視覺定義：如何使用附圖

附圖是「主編輯器／穿搭階段」的視覺基準。人物、背景、衣物、選取框與所有控制項必須分離。圖中的人物接近 L2 照片效果，P0 L1 應改用有臉部、手腳、髮型與自然比例的時裝畫替身。不得再用橢圓頭、長方形身體與矩形衣服當正式畫面素材。

整體：奶油白底、深墨色文字、酒紅重點色、暖色咖啡廳情境；細線圖示、柔和陰影、克制的透明材質。替身採簡化寫實的時裝畫；道具可用有細描邊的貼紙插畫。畫面要讓衣服與人物成為焦點。

### 主畫面由上到下

1. SafeArea 與標題「穿搭預演」，副標「買之前，先看看穿上的自己」，右側作品收藏入口。
2. 場景縮圖膠囊與「我的替身」按鈕。
3. 大幅畫布：完整頭腳可見；場景 cover、人物 contain；左下復原／重做，右下圖層入口。選取時才顯示衣物控制框。
4. 階段進度：素顏 → 保養 → 整理 → 穿搭 → 登場。附圖省略素顏，實作保留五階段；素顏可用起點圖示讓窄螢幕不擁擠。
5. 底部工具面板：依階段切換內容。穿搭時為上身、下身、鞋包、道具、場景；第一張卡為匯入截圖，其餘為素材。
6. 固定底部操作：儲存與「完成穿搭」。完成按鈕不因滑動素材而消失。

約 390×844 的手機以畫布最大為原則；小螢幕縮減頂部留白，工具列內部捲動，保留完整操作。至少驗證 360×800、390×844、430×932。平板／桌面可採畫布＋側邊工具面板。鍵盤或面板打開時不溢位。體型面板預設關閉，不遮住初始主畫面。

## 5. 頁面與主要流程

### 5.1 首次進入

不要求註冊。簡短說明產品用途，提供「建立我的替身」與「先試玩」。試玩使用可修改的預設體型與內建素材；建立替身要求性別表現、身高、胸腰臀。不要把試玩限制成不可儲存。

首次引導第一步是貼一張痘痘貼：動態手指與虛線軌跡，點擊或拖曳成功後隱藏，再提示匯入想買的衣服。引導可跳過；完成狀態本機記錄，不每次重播。

### 5.2 我的替身

以底部面板或獨立頁顯示體型設定。必填參數為性別表現、身高、胸圍、腰圍、臀圍；選填為肩寬、膚色 8 階、臉型。數值輸入與 slider 同步、顯示單位，不以梨形等分類取代連續數值。

數值邊界依實際插值模型集中定義；至少攔截空值、非數值、非正值與模型無法處理的值。超出支持範圍要說明，不默默改值。不得用未驗證公式宣稱醫療或人體測量精度。

編輯時預覽，按「套用」才更新作品；取消還原。已吸附服裝隨錨點重算，未吸附服裝保持畫布位置。套用是一次可復原操作。

### 5.3 衣物匯入

入口 → 選圖 → 圖片方向校正／裁切 → 去背編輯 → 指定類別與名稱 → 加入衣櫥 →「立即試穿」或「繼續匯入」。

支援 JPEG、PNG 與平台解碼器可處理的相片格式；不支援格式明示。大圖按記憶體預算降採樣，保留比例與透明度，不一次解碼大量原始照片。權限被拒時提供開設定或改用檔案選取；使用者取消不當作錯誤。

去背編輯提供原圖／結果切換、棋盤透明底、縮放平移、可調筆刷的擦除與還原、局部復原及重新開始。還原從原圖與遮罩恢復。輸出透明 PNG，不把棋盤格烘焙進圖片。全透明結果不能儲存；可取消處理，處理中防止重複提交。

iOS 17+ 可用 Vision foreground instance mask；Android 使用實際可用的 ML Kit Subject Segmentation，須確認 SDK 支援、模型下載與裝置條件。平台能力在執行時檢查。Web 或其他不支援平台直接提供手動模式，不能假裝自動去背成功。

「點選主體」只保留模型能分辨的被點選 instance；衣架與衣物若被模型視為同一 instance，仍需手動擦除。多件平鋪也不保證能分開。模特兒圖連人保留時，提示作為「穿著參考」自由貼紙；MVP 不承諾只取衣服。

單品類別含 top、outer、bottom、shoes、accessory、hairFront、hairBack、expression、prop；另設 reference 類型或 metadata，穿著參考不預設自動吸附。來源網址為可選欄位，禁止直接執行任意 URI scheme。

### 5.4 衣櫥

依類別篩選，顯示透明縮圖、名稱、最近匯入；支援加入畫布、重新命名、刪除。沒有素材時顯示匯入入口並保留內建素材。

刪除衣櫥單品不破壞既有作品；作品持有自己的素材引用，只有沒有任何作品或草稿引用的檔案才能清理。

### 5.5 場景與主題

場景入口打開內建清單與相簿匯入，選擇即預覽，可取消。替換場景不重設服裝。背景 cover，可拖曳調整取景，取景資料可儲存。

P0 一組「週末咖啡廳」主題：一個預設場景、一組髮型、建議服裝及至少 8 個保養／配件道具。套用整包時保留自訂單品；會取代現有內容時先明示影響並可取消。整包套用為一次 undo。

### 5.6 登場、儲存、分享

保養、整理與穿搭不強制按順序鎖住。使用者隨時可完成，不要求每類都穿齊。階段勾選由實際操作產生；移除相應內容後重算。素顏初始快照在建立本次變身時保存，重新開啟作品不偷偷覆寫。

完成時播放約 1.5 秒揭曉動畫，支援減少動態效果。進入結果頁，顯示前後對比、作品名稱、「繼續編輯」「儲存作品」「分享／匯出」。快照不包含選取框、工具列、手勢提示與系統 UI。

儲存保留可編輯資料與前後 PNG，不只是截圖。匯出提供單張完成圖與前後對比卡。原生平台使用分享面板／相簿支援；Web 提供檔案下載。權限或分享失敗保留作品並允許重試。

作品清單支援縮圖、名稱、更新時間、重新編輯、重新命名、刪除確認及空狀態。從作品複製新的變身不覆蓋原件。

## 6. 畫布引擎與互動規格

### 圖層順序

| Z | 內容 | 錨點 |
|---|---|---|
| 0 | 背景 | 無 |
| 1 | 後髮 | headTop |
| 2 | 替身 | 無 |
| 3 | 表情 | faceCenter |
| 4 | 下身與鞋 | waistCenter；鞋可用 ankleCenter |
| 5 | 上衣與外套 | shoulderCenter |
| 6 | 前髮 | headTop |
| 7 | 道具與自由參考貼紙 | 無／自由 |

同層以 order 排序；排序命令限於同一語意層，避免後髮移到身前。前後髮為一組資產，可共同選擇／移除，仍分層渲染。正式 L1 臉部已有基本五官，表情素材可以在後續擴充，不作 P0 核心阻礙。

所有等級沿用 headTop、faceCenter、chin、neck、shoulderLeft、shoulderRight、shoulderCenter、chestCenter、waistCenter、hipCenter、kneeCenter、ankleCenter、handLeft、handRight。錨點使用替身局部正規化座標；畫布存 x/y 相對寬高、scale 相對替身高度、rotation 弧度。渲染與手勢轉換由單一座標服務處理。

點素材卡直接加入並吸附；長按拖出則依落點加入。單指拖曳；雙指在同一 gesture session 內同時縮放／旋轉，避免跳動。點選使其到同層最前；點空白取消選取。長按選單含同層最前／最後、貼回錨點、移除。圖層面板可選取被遮住的單品。

對位點為圖片上與錨點相接的位置，例如上衣上緣中心。預設寬為兩肩距離乘倍率：上衣 1.15、外套 1.3、褲 1.0、鞋 0.9、前髮 0.7、表情 0.45、道具 0.4。值集中於類別設定並允許素材 override。scale 限制在替身高度 3%–200%，命中範圍考慮旋轉與透明留白。

拖離解除吸附，放開時「對位點」距錨點 24 logical px 內重新吸附。高亮提示配合可選輕觸回饋；不支持震動時正常運作。拖出可視區仍需有重新選取／貼回的方法，不能讓圖層永久遺失。

拖曳中 105% 視覺放大、輕微陰影與傾斜只屬互動效果，不寫入儲存 transform。工具列來源保留 0.3 透明度殘影。不要與使用者實際旋轉混淆。

復原／重做涵蓋新增、移除、一次完整手勢、排序、場景替換、體型套用、主題套用；至少保留本次 session 50 步。連續 pointer move 不逐幀建立歷史。新操作清空 redo；沒有歷史時按鈕禁用。縮放螢幕後可視位置仍正確。

道具：至少痘痘貼可拖到臉部後觸發貼上／淡出效果，精華可觸發塗抹視覺回饋。可重播或重設，不永久刪掉使用者素材。其餘道具可移動、縮放、移除；不把每張圖片都假稱有獨特動畫。

## 7. 儲存與資料設計

保留既有可行的 ChangeNotifier + ListenableBuilder 架構；避免只為換框架重寫。本機資料庫優先 Drift；若現有專案已有可工作的儲存方案，可保留並滿足同樣契約。Web 與原生需使用各自支援的持久化 adapter。儲存服務介面與 UI 分離。

必要實體：BodyProfile、Asset、WardrobeItem、Scene、ThemePack、CanvasDocument、SavedOutfit、AppPreferences。每個可變資料含穩定 id、createdAt、updatedAt；文件含 schemaVersion，升級時提供遷移或明確可恢復錯誤，不能靜默清空資料。

CanvasDocument 至少保存 bodyParams、avatarLevel、avatarScale、avatarPosition、sceneId、sceneCrop、layers、stageProgress、beforeSnapshotAssetId、name、updatedAt。圖層含 id、itemId、kind、z、x、y、scale、rotation、snappedTo、order。與現有 toJson 格式映射一致；保留 snake_case 或明確遷移，不同平台不要各自發明格式。

示例：

```json
{"schemaVersion":1,"layers":[{"id":"L3","item_id":"tee_white","kind":"top","z":5,"x":0.5,"y":0.42,"scale":0.31,"rotation":-0.04,"snapped_to":"shoulderCenter","order":3}]}
```

圖片存為 app 管理的檔案或 Web blob 持久化資料，以穩定 assetId 引用；不要把暫時選圖路徑當永久位置。先確保素材寫入成功再提交文件，失敗時可回復。匯出圖與可編輯文件分開管理。

每次操作結束後 debounce 自動存草稿；切到背景時盡力 flush，但不依賴關閉事件才儲存。顯示「儲存中／已儲存／儲存失敗」。顯式儲存失敗不得顯示成功，也不能離開後丟失記憶體狀態。回訪自動恢復草稿，提供新建入口；新建前保存或確認捨棄。

Supabase 不屬 P0 依賴。未來同步再沿用 v3 schema，補 RLS、使用者檔案隔離、Storage 權限與遷移。不可把 service-role key 放進客戶端，不預先加入沒有接通的登入流程。

## 8. 素材交付要求

至少一套真正可變形的 L1 時裝畫基底，控制點／輪廓與五個主要體型參數連動。不能只整張圖片等比例拉寬來宣稱胸腰臀獨立變形。左右肢體與關節要保持連續；參數極值不破圖。

至少：5 個場景、3 件上衣、2 件外套、3 件下身、2 雙鞋、2 個包／配件、1 組前後髮、8 個主題道具。這是可操作內容下限，不代表三組正式主題全部完成。

每個素材包含 id、名稱、類別、透明圖片／向量、比例、對位點、寬度倍率、圖層、授權來源。照片使用合法自有或明確授權資源，不抓 IG／小紅書圖片。隨專案附素材清單與授權記錄；執行不依賴遠端熱連圖片。

參考圖中的真人、衣服與場景不自動等於已取得可獨立使用素材。可以另製符合方向的素材，但需清楚列出美術差距；不把整張 mockup 切幾塊假裝為可換裝角色。若正式美術缺失，可先交可用替代版本，但不得稱為視覺驗收完成。

## 9. 工程與品質

開始時確認實際 Flutter stable 版本與依賴相容性，再記錄 SDK 版本；不要只照抄 v3 的「Flutter 3.47」而不查驗。提供 lockfile、README、啟動指令、平台支援表與原生設定。沒有 macOS／Xcode 時不能宣稱 iOS 編譯或 Vision 真機驗證通過。

建議結構沿用 core/anchors、core/layer、features/avatar、canvas、wardrobe，新增 import、projects、export、persistence、platform segmentation adapters；以專案現有慣例為先。

圖片解碼、去背與匯出避免阻塞手勢。滑動與拖曳以流暢為目標，實際性能需在目標裝置量測；選取變更避免重建整個素材庫。縮圖與完整素材分開快取，釋放不用的 image handles。

錯誤必須可理解且可重試：圖片讀不到、格式不支援、模型不可用、處理逾時、磁碟不足、資料損毀、匯出／權限失敗。不顯示未處理的 stack trace；開發 log 不寫入自拍、身體參數或秘密值。

隱私：照片與身材資料預設留在裝置；P0 不自動上傳。提供刪除個別作品與清除本機資料，後者明確確認。減少動態效果、螢幕閱讀標籤、文字放大與非顏色狀態提示須可用。

## 11. 實作順序與交付格式

1. 稽核現有專案，建立可啟動基準與缺口表。
2. 建立設計 token 與主畫面骨架，接入獨立可操作素材。
3. 完成 L1、圖層、手勢、吸附、undo／redo。
4. 完成本機資料層，先跑通儲存與重開。
5. 完成匯入、手動修圖及可用平台的自動去背。
6. 完成主題道具、登場、作品管理與匯出。
7. 執行功能與視覺驗收、修復錯誤，補 README 與支援表。

每一階段交付能執行的增量，持續做到 P0 完成；不要停在計畫、靜態畫面或第一個 build 成功。非必要的外部功能不阻塞本機完整流程。

最後交付：可執行程式碼、合法素材與來源清單、安裝／啟動文件、支援平台、測試結果（命令與通過／失敗／未執行分列）、A01–A20 驗收表、主畫面／體型／匯入／作品／對比卡實際截圖，以及尚未完成或需要真機驗證的項目。若仍有 P0 缺口，明確寫出，不能以「完整產品」掩蓋。
